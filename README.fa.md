# زیرساخت ترکیبی وب و ایمیل سازمانی

## اطلاعیه مطالعه موردی ناشناس

این مخزن یک مطالعه موردی ناشناس برای نمونه‌کار است. این مخزن نه وب‌سایت تولیدی است، نه پشتیبان زیرساخت، و نه مخزن استقرار. هویت شرکت، دامنه‌ها، نام میزبان‌ها، آدرس‌های شبکه، اعتبارنامه‌ها، خروجی‌های پیکربندی، تصاویر و سورس تولید به‌صورت عمدی حذف شده‌اند.

## نمای کلی

این پروژه یک سایت GitHub Pages چندزبانه درباره پروژه زیرساخت وب، ایمیل و شبکه ترکیبی است که توسط Milad انجام شده است. مطالعه موردی تصمیم‌های مهندسی، مسئولیت‌ها و روال‌های عملیاتی پشت یک پلتفرم یکپارچه برای تحویل وب‌سایت، میزبانی Linux، ایمیل سازمانی، دسترسی امن بیرونی و اتصال داخلی مسیریابی‌شده را توضیح می‌دهد.

## چالش پروژه

سازمان به پلتفرمی قابل نگهداری برای وب‌سایت عمومی، میزبانی متمرکز وب و ایمیل، دسترسی قابل اتکای داخلی و بیرونی، سرویس‌های امن‌شده با TLS، احراز هویت ایمیل مبتنی بر DNS، مسیرهای کنترل‌شده ارسال خروجی، آمادگی پشتیبان‌گیری و مستندات عملی عیب‌یابی نیاز داشت.

## نقش من

Milad لایه وب‌سایت را طراحی و پیاده‌سازی کرد، محیط میزبانی را مستقر کرد، سرویس‌های Linux را اداره کرد، HestiaCP، Nginx، Exim، Dovecot و Roundcube را پیکربندی کرد، رفتار Reverse Proxy را یکپارچه کرد، احراز هویت DNS را هماهنگ کرد، مفاهیم اتصال امن را پیکربندی کرد و روندهای بازیابی را مستند کرد.

## مسئولیت‌ها

- طراحی و پیاده‌سازی وب‌سایت.
- استقرار وب‌سایت و مدیریت میزبانی.
- مدیریت سرور Linux و اعتبارسنجی سرویس‌ها.
- مدیریت HestiaCP، Nginx و TLS.
- مدیریت Exim SMTP، Dovecot IMAP و Roundcube webmail.
- برنامه‌ریزی دسترسی داخلی و بیرونی.
- یکپارچه‌سازی HAProxy، WireGuard و MikroTik RouterOS.
- هماهنگی Firewall، NAT و Policy-Based Routing.
- مفهوم‌پردازی SMTP خروجی بر اساس دامنه.
- برنامه‌ریزی پشتیبان، پایش، عیب‌یابی و مستندسازی بازیابی.

## معماری سطح بالا

معماری عمومی‌شده شامل کاربران بیرونی، کاربران داخلی، Public DNS، یک European VPS، HAProxy، رفتار SMTP Relay، تونل امن WireGuard، MikroTik Edge Router، Reverse Proxy Server، HestiaCP Web and Mail Server، Nginx، Exim، Dovecot، Roundcube، فضای پشتیبان، پایش و لاگ‌ها است.

هیچ IP، دامنه، نام میزبان، نام رابط شبکه، نام ارائه‌دهنده یا مقدار دقیق مسیریابی واقعی منتشر نشده است.

## کار وب‌سایت و میزبانی

بخش وب شامل لایه ارائه وب‌سایت، میزبانی Linux، مدیریت HestiaCP، میزبانی Nginx، یکپارچه‌سازی Reverse Proxy، مدیریت HTTPS و TLS، تحویل دارایی‌های ایستا و Health Check پس از تغییرات است. سورس تولید و محتوای اصلی شرکت در این مخزن وجود ندارد.

## زیرساخت ایمیل

بخش ایمیل شامل Exim SMTP، Dovecot IMAP، Roundcube webmail، دسترسی ایمیل امن‌شده با TLS، دسترسی داخلی و بیرونی به صندوق‌ها، احراز هویت DNS و مفاهیم کنترل ارسال خروجی است. Milad این فناوری‌ها را پیکربندی، اداره و عیب‌یابی کرده است؛ مطالعه موردی ادعا نمی‌کند که او این نرم‌افزارها را توسعه داده است.

## دسترسی داخلی و بیرونی

کاربران داخلی از مسیر شبکه سازمان به سرویس‌ها دسترسی داشتند. کاربران بیرونی از طریق European VPS عمومی‌شده و لایه Proxy یا Relay به نقاط ورود منتخب می‌رسیدند. توضیح عمدا مفهومی است و آدرس‌ها یا قوانین دقیق را حذف می‌کند.

## اتصال ترکیبی

پروژه از مفهوم تونل امن میان موقعیت‌های زیرساختی استفاده کرد. MikroTik RouterOS مسئول Edge Routing، مرزهای Firewall، NAT و Policy-Based Routing بود.

## مفهوم SMTP Routing بر اساس دامنه

ارسال ایمیل خروجی پیرامون مسیرهای مستقیم و Relay برنامه‌ریزی شد. این نمونه‌کار مفهوم را بدون دامنه واقعی، selector، مقدار DNS، اعتبارنامه یا پیکربندی Relay توضیح می‌دهد.

## DNS و احراز هویت ایمیل

SPF، DKIM، DMARC، MX و PTR به‌عنوان مفاهیم هویت ایمیل، قابلیت تحویل و اعتماد در نظر گرفته شدند. مقدار واقعی رکوردها در این مخزن وجود ندارد.

## رویکرد امنیتی

کار امنیتی بر TLS، کاهش سطح در معرض دسترس، مرزهای Firewall، بهداشت اعتبارنامه‌ها، جداسازی پیکربندی، بازبینی حریم خصوصی، مدیریت پشتیبان و مستندسازی عمومی امن تمرکز داشت.

## پشتیبان‌گیری و بازیابی

مطالعه موردی برنامه‌ریزی پشتیبان، اعتبارسنجی بازیابی و روند بازیابی رخداد را به‌صورت پاک‌سازی‌شده توضیح می‌دهد. لاگ واقعی، مسیر فایل‌سیستم، تاریخچه دستورها و جزئیات تأییدنشده رخداد حذف شده‌اند.

## عیب‌یابی

عیب‌یابی به‌عنوان یک فرآیند ساختارمند ارائه شده است: مشاهده علائم، جداسازی لایه‌ها، بررسی سلامت سرویس، تعیین دسته علت ریشه‌ای، بازیابی مؤلفه‌های لازم، اعتبارسنجی رفتار و مستندسازی اقدامات پیشگیرانه.

## اجرای محلی نمونه‌کار

چون ترجمه‌ها از فایل‌های JSON بارگذاری می‌شوند، از یک HTTP server محلی استفاده کنید:

```bash
python3 -m http.server 8080
```

سپس سرور محلی را در مرورگر باز کنید. باز کردن مستقیم با `file://` ممکن است در بعضی مرورگرها JSON را بارگذاری نکند.
